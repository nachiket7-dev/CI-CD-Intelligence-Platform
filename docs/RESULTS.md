# CI/CD Intelligence Platform: Experimental Results

## Honest Limits and Simulator Assumptions

> **All primary evaluation figures below are derived from synthetic data generated by a seeded simulator.**

1. **Synthetic Generation**: CI runs, workflows, failure events, author historical records, and queue depth spikes are produced by a parameterized stochastic simulator. While scenarios model realistic engineering profiles (such as flaky integration tests, risky dependency upgrades, and busy queue bottlenecks), the results reflect the simulator's generative assumptions rather than production GitHub repositories.
2. **Pre-Run Temporal Boundary**: Features represent strictly pre-run metadata known before job execution commences. No post-run outcomes, durations, runtime log extracts, or exit codes are accessible during scoring.
3. **Decision Support Scope**: The model provides risk visibility to developers and operators; it does not automatically cancel runs or bypass required checks. Signals represent model associations and are not proven causal explanations.

## Analysis of the Four Plan Success Measures

### 1. Beats the Baseline
On synthetic runs generated by the seeded simulator across multiple independent seeds, the candidate gradient boosting model consistently outperforms both the majority-class baseline and the logistic regression baseline on PR-AUC (averaging 0.349 ± 0.030 vs 0.337 ± 0.033 for logistic regression) and achieves non-zero recall (0.144 ± 0.081) at the 50% precision threshold, clearing the promotion gate in 4 of 5 seeds (80%). However, these numbers do not support claims of superior performance in real-world engineering environments: the candidate model's advantage is established only under the simulator's parameterized distributions and synthetic noise, and performance in arbitrary external production pipelines cannot be inferred from these simulator runs alone.

### 2. No Leakage
The feature contract verification and ablation study confirm that every input feature is strictly known before run execution, with the ablation experiments demonstrating expected drops in discriminative performance when removing predictive groups like rolling workflow history (-0.0140 PR-AUC) and queue/timing metrics (+0.0102 PR-AUC). Furthermore, injecting the forbidden post-run duration field (`duration_s`) is caught loudly by the contract checker and rejected by the promotion gate without silent bypass. What these numbers do not support is immunity against real-world telemetry collection bugs or unmodeled external leakage (such as build artifact timestamps or developer timezone anomalies in live telemetry) that fall outside the explicit column definitions of the contract.

### 3. Calibrated
Platt calibration lowers the candidate model's Brier score across seeds (0.1440 ± 0.0085 compared to uncalibrated probability outputs) and ensures that predicted failure probabilities closely align with empirical outcomes across the evaluated risk bands under normal test distributions. What these numbers do not support is calibration stability under severe distribution shift or in completely novel repositories: as shown in the leave-one-scenario-out evaluation, when a model encounters an environment it never saw during training, its confidence estimates can diverge from actual failure frequencies, meaning that probability thresholds must be re-evaluated when operating in unfamiliar CI environments.

### 4. Works on Real Data (Optional)
The real-data evaluation pipeline and contract loader demonstrate that the platform can ingest public GitHub Actions metadata (DOI 10.17632/mggwn7rj9f.1), enforce strict pre-run column filtering, drop target-leaking fields, and execute temporal train-validation-test splits without synthetic imputation. What the numbers do not support is the assumption that public dataset metadata is sufficient for high-accuracy pre-run prediction: because real-world public traces omit granular build signals (such as dependency file diffs, AST changes, and runner queue depths), the model's discriminative power on real data is substantially constrained compared to the synthetic benchmark, proving that pre-run intelligence is fundamentally bottlenecked by telemetry availability rather than algorithm complexity.
